# 微信公众平台html

Use this skill for two related workflows:

1. Turn a draft article into generated WeChat HTML files.
2. Extract compact hyperlink-template HTML from a full `mp.weixin.qq.com` source page.

For generated draft articles, output two files:

1. `*.full.html`: a complete browser-preview document with `<!doctype html>`, `<html lang="zh-CN">`, `<head>`, the fixed preview CSS, and real images preserved when provided.
2. `*.wechat-fragment.html`: the literal "去头尾 HTML，可搬运到微信平台" version, generated by stripping `doctype/html/head/style/body/main` from `*.full.html` while preserving the article body and its existing image tags. This file is the local browser preview of the pasteable body fragment. If it still uses local or relative image URLs such as `assets/...`, it will preview locally but those images will not survive a WeChat backend paste by themselves.
3. `*.wechat-bridge-fragment.html` or `*.wechat-bridge-fragment.template.html`: the preferred WeChat-import version when the article contains local images and the user is willing to make them temporarily public. It contains only the article body fragment and must not include `doctype/html/head/style/body/main`. Local body images should point at temporary public HTTPS URLs so the WeChat editor can fetch them and, after saving the draft, rehost them to WeChat CDN.
4. `*.wechat-fragment.placeholder.html`: the manual-upload fallback. It contains only the article body fragment and must not include `doctype/html/head/style/body/main`. Replace every local image with an equal-ratio placeholder rectangle that tells the user which local image to upload there.

The bundled visual baseline is `assets/template-culture-shirt.html`, copied from `文化衫｜全员鄂人，等你一人.html`. The generator recreates its core components: deep-red section headers, 14px / 1.8 body text, editor-note block, image spacing, credits, and optional bottom quote card.

## Workflow

### Draft-to-HTML generation

1. Parse the user's push content into a JSON spec. If images are mentioned, create one `image` block per image with a clear `label`. Include `src`/`path` only when the user supplied an actual URL or local path.
2. Run `scripts/generate_wechat_html.py <spec.json> --out-dir <output-dir>`.
3. Generate `*.wechat-fragment.html` by extracting the article body from `*.full.html` and preserving image tags. This file should not contain placeholder rectangles.
4. If local body images are present, default to the bridge workflow described in **Default local-image bridge command**. Keep `*.wechat-fragment.placeholder.html` as a manual-upload fallback when useful unless the user asks not to.
5. Return the generated file paths. Call the final `*.wechat-bridge-fragment.html` file "去头尾 HTML，可搬运到微信平台" when it has real temporary public image URLs. If only `*.wechat-bridge-fragment.template.html` exists, say it still needs a public base URL before pasting into WeChat. Remind the user never to paste the complete `*.full.html` file into the WeChat editor/plugin source box.

Prefer writing the JSON spec in the current project/workspace, not inside the skill folder.

The current generator is still hardcoded to the red culture-shirt visual system. If the user explicitly wants 惟楚有材蓝色 or 惟楚有材红色, use the corresponding template folder as the visual/reference source. Do not claim the JSON generator can automatically render those styles unless it has been extended.

### Source-link extraction

When the user provides a public WeChat article URL and wants a reusable template or a compact hyperlink HTML:

1. Fetch the full page with `curl -L` into the working project or template folder, not into the skill folder. Prefer naming it `full.html`. `source.full.html` and `source.raw.html` are older synonyms.
2. Run:

```bash
python3 /Users/AntiEntropy/.codex/skills/wechat-public-platform-html/scripts/extract_wechat_article_html.py \
  full.html \
  --source-url 'https://mp.weixin.qq.com/s/...' \
  --out hyperlink.html
```

3. If this is intended as a reusable template, also copy `hyperlink.html` to `source.html`.
4. For compatibility with older folders, it is fine to also keep `source.full.html`, `source.raw.html`, `source.hyperlink.html`, and `source.article.html`, but new folders should prefer `full.html` and `hyperlink.html`.
5. Keep `full.html` when future re-extraction may be useful, but use `source.html` / `hyperlink.html` as the default lightweight preview/reference and as the preferred base for derived posts.

Use this extraction route to avoid the full WeChat runtime page size. Raw `mp.weixin.qq.com` pages are often about 2.8-3.0 MB; the extracted article/template HTML is usually about 28-45 KB and is much closer to the useful editor content.

The compact hyperlink output must force `#js_content` visible. WeChat source pages often mark the article body as `visibility: hidden; opacity: 0;` and rely on WeChat runtime JavaScript to reveal it; static local previews do not run that runtime.

## JSON Spec

Use this shape:

```json
{
  "title": "活动标题",
  "editor_note": {
    "label": "编者按",
    "text": "开头导语。也可以用 html 字段放内联加粗。"
  },
  "sections": [
    {
      "heading": "活动亮点",
      "blocks": [
        { "type": "paragraph", "html": "<strong>轻松加入：</strong>不需要提前准备。" },
        { "type": "paragraph", "html": "<strong>内容丰富：</strong>摊位包含手作、桌游、摄影。" }
      ]
    },
    {
      "heading": "现场剪影",
      "blocks": [
        {
          "type": "image",
          "label": "现场剪影 01｜主视觉横图",
          "path": "/absolute/local/image.jpg",
          "ratio": 1.3333333,
          "data_w": 1080,
          "width": "100%"
        }
      ]
    }
  ],
  "credits": ["策划：宣传部", "编辑：某某"],
  "footer_card": {
    "text": "惟楚有材，于斯为盛。",
    "image": {
      "label": "底部卡片｜协会图片",
      "ratio": 1.5384615,
      "width": "76%"
    }
  }
}
```

Notes:

- `ratio` means width / height. If unknown, infer from the image file when possible; otherwise use `1.3333333` for landscape, `0.75` for portrait, or ask only if the image placement depends on exact shape.
- `width` controls displayed width and accepts values like `"100%"`, `"76%"`, or `"73%"`.
- Use `html` for paragraphs when bold labels are needed, for example `<strong>报名方式：</strong>扫描二维码加入群聊。`
- The full HTML preserves image URLs/local paths. Local absolute paths become `file://...` for browser preview.
- The literal "去头尾 HTML，可搬运到微信平台" output (`*.wechat-fragment.html`) preserves image tags from `*.full.html`. If a manual-upload fallback is needed, name it `*.wechat-fragment.placeholder.html`.

## Image URL Strategy

For local interview photos or event photos, do not expect the WeChat public platform backend to load `file://`, absolute local paths, or relative `assets/...` paths after paste. For images extracted from an existing public WeChat article, first check whether the original `src` / `data-src` already points to a WeChat CDN such as `mmbiz.qpic.cn`, `mmbiz.qlogo.cn`, or `mmbiz.qpic.cn/sz_mmbiz_*`; public-account articles often already carry stable WeChat CDN image URLs.

Default preference for local body images: first keep `*.wechat-fragment.html` as the stripped-body local preview with real image tags, then use the verified temporary-public-image bridge when the user has approved making those images briefly public. Keep equal-ratio placeholder output as `*.wechat-fragment.placeholder.html` for privacy-sensitive images, missing public hosting, or when the user asks for manual upload.

### Default local-image bridge command

After generating or otherwise preparing a browser-preview `*.full.html` with local body images, run:

```bash
python3 /Users/AntiEntropy/.codex/skills/wechat-public-platform-html/scripts/prepare_wechat_image_bridge.py \
  "$POST_DIR/$POST_NAME.full.html" \
  --copy-to "$POST_DIR/bridge-site/public/images" \
  --base-url "$PUBLIC_BASE_URL" \
  --out "$POST_DIR/$POST_NAME.wechat-bridge-fragment.html" \
  --manifest "$POST_DIR/wechat-image-bridge-manifest.md"
```

If `$PUBLIC_BASE_URL` is not settled yet, use `--base-url '__BRIDGE_BASE_URL__'` and name the output `*.wechat-bridge-fragment.template.html`; after deployment, replace `__BRIDGE_BASE_URL__` with the final HTTPS site URL and write `*.wechat-bridge-fragment.html`.

The bridge fragment is the preferred "去头尾 HTML，可搬运到微信平台" file for WeChat when it contains real HTTPS image URLs. Paste/import it, save the draft, reopen or inspect source, and confirm all temporary-public image URLs were rewritten to WeChat-owned `mmbiz.qpic.cn` / `mmbiz.qlogo.cn` URLs before deleting or unpublishing the temporary host.

Use one of these strategies:

1. Preferred local-image bridge: generate a preview HTML with real local images, temporarily host those images at a public HTTPS URL, then generate a "去头尾 HTML，可搬运到微信平台" file (`*.wechat-bridge-fragment.html`) with those HTTPS URLs. The WeChat editor should fetch them during paste/save and can rehost them to WeChat CDN. Ask/confirm before making private or unpublished local photos publicly reachable.
2. If the image already has a stable WeChat CDN URL such as `mmbiz.qpic.cn` or `mmbiz.qlogo.cn`, preserve that remote URL in `src` and `data-src`. This is usually the best route for articles derived from another public WeChat article: it avoids local upload placeholders, avoids base64, and avoids relying on a third-party cloud host. Still save and reopen the draft once to confirm the images display in the WeChat editor.
3. Manual-upload fallback: generate a preview HTML with real local images, keep `*.wechat-fragment.html` as a true stripped-body fragment, and generate a separate `*.wechat-fragment.placeholder.html` with equal-ratio placeholder blocks plus an `image-manifest.md`; the user manually uploads each local image in the WeChat editor.

Mainland-friendly temporary image hosts should prefer China mainland cloud object storage plus CDN, for example Tencent Cloud COS + CDN, Alibaba Cloud OSS + CDN, Qiniu Kodo + CDN, or UpYun. Avoid Google Drive, GitHub raw links, and overseas-only storage for WeChat paste/import workflows because mainland access may be blocked or slow. For any object-storage bridge, ensure public read access, correct image content type, no hotlink protection that blocks `mp.weixin.qq.com`, and a URL that the WeChat backend can fetch without login or cookies.

When validating the bridge workflow, use a three-sample test fragment:

- A WeChat CDN image (`mmbiz.qpic.cn`) as the control.
- A non-WeChat public image URL as the third-party-host test.
- A small `data:image/...;base64,...` image as the inline-image test.

After pasting into the WeChat editor, save the draft and inspect the reopened draft/source. If the third-party URL has been rewritten to a WeChat media/CDN URL such as `mmbiz.qlogo.cn` or `mmbiz.qpic.cn`, temporary object-storage URLs can be used as an upload bridge. If it remains third-party, treat the URL as a publication dependency. In the 2026-06-12 test, the third-party sample was rewritten to `mmbiz.qlogo.cn`, while the `data:image/...;base64,...` sample stayed as data URI and triggered/appeared related to a "图片粘贴失败" warning; do not prefer base64 inline images for production. A local copy of this protocol exists at `/Users/AntiEntropy/Documents/Research/wechat-xiumi-post/templates/招生/rehost-test/`.

## WeChat Cover Sizes

For WeChat public-account cover assets, use the two-ratio splice workflow by default when the user mentions the cover/crop workflow:

- Wide cover: `2538x1080` pixels, aspect ratio `2.35:1`.
- Square share cover: `1080x1080` pixels, aspect ratio `1:1`.
- Combined upload/crop helper image: `3618x1080` pixels, made by placing the `2538x1080` wide cover on the left and the `1080x1080` square cover on the right.

For generated posts, store these under the post's `assets/wechat_cover_outputs/` directory with names like:

- `*_cover_2_35x1.png`
- `*_cover_1x1.png`
- `*_cover_combined_for_wechat_crop.png`

For admissions or contact-information posts, keep dense phone tables out of the cover. Prefer a clean visual entry point with the article title, year, campus/source identity, and a small set of symbolic elements such as a location pin, phone icon, map silhouette, or campus image.

## Important Rules

- Never paste a complete HTML document into the WeChat public platform editor or the Chrome helper source box. It will render `<style>body {...}</style>` as article text. Paste only the "去头尾 HTML，可搬运到微信平台" content from `*.wechat-fragment.html`.
- Keep styles inline. WeChat strips or changes many external/global CSS rules.
- Use the stable table-based editor-note block generated by the script; it avoids the original float/inline-block "编者按" drifting after paste.
- For user-facing guidance, avoid abstract names like "可粘贴片段" when possible. Say: use `*.wechat-fragment.html` for local preview of the stripped body; for production WeChat import with local photos, use `*.wechat-bridge-fragment.html` after the temporary public URLs are ready. If using the manual fallback, import `*.wechat-fragment.placeholder.html`, then delete each placeholder rectangle and use WeChat's own "图片 -> 本地上传" to insert the matching local image.
- For source extraction, keep both full and compact files when archiving a template: `full.html` for provenance, `hyperlink.html` for the extracted preview/editing base, and `source.html` as the default template entry. Older folders may still have `source.full.html`, `source.raw.html`, `source.hyperlink.html`, and `source.article.html`.
- For template-based rewriting, especially 惟楚有材蓝色/红色, start from `hyperlink.html` or `source.html`. Treat full/raw WeChat pages as provenance and recovery material only, because replacing visible `#js_content` in full HTML can leave stale old article text in scripts and metadata.
